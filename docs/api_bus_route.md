# 버스노선 OpenAPI 명세 정리

원본: `참고자료/OPENAPI 활용자가이드_버스노선_v1.2.pdf` (한국교통안전공단 / 위니텍 컨소시엄)
공공데이터포털: 국토교통부_버스노선 https://www.data.go.kr/data/15142030/openapi.do
용도: **노선번호(`rte_no`) ↔ 노선ID(`rte_id`) 매핑**. 혼잡도 데이터와는 `rte_id`로 연결한다.

## 3. 지역코드 주의 (실제 호출로 확인, 2026-10-01)
같은 원주시인데 **날짜와 API에 따라 코드가 다르다.**

| 날짜 | 혼잡도 API | 버스노선 API |
|---|---|---|
| 2026-01-01 | `51` / `51130` | **`42` / `42130`** (`51`은 NO_DATA_FOUND) |
| 2026-04-15 | `51` / `51130` | **`42` / `42130`** |
| 2026-09-01 | — | `51` / `51130` |

- 버스노선은 `ctpv_cd=51`로 먼저 요청하고, `NO_DATA_FOUND`이면 `42`로 다시 요청한다.
- 원주 필터: `sgg_cd in ("51130", "42130")`.
- **두 API를 지역코드로 조인하지 않는다. `rte_id`로만 연결한다.**

## 5. 데이터 특성 (2026-01-01 원주 기준 실측)
- **모든 행이 2번씩 중복**된다 (1,008행 → 고유 `rte_id` 504개). `rte_id` 기준으로 중복 제거.
- 혼잡도 하루치의 고유 `rte_id` 113개가 **전부** 노선 목록에 존재 → `rte_id` 조인 신뢰 가능.
- `rte_id`는 안정적(1월→9월: 사라진 ID 0, 새 ID 8). 하지만 **`rte_no` 표기는 바뀔 수 있다** (예: `43703019` `55경동대` → `55(경동대-부론)`).
- **노선번호 하나에 `rte_id`가 여러 개** (경유지·종료지·첫차·하교 변형). 예: 34번 → `34연세대`, `34매지리`, `34상촌-연세대`, `34연세대종료` … 정확히 `"34"`인 `rte_no`는 없음.
- 중간 경유 정류장 정보는 없다(출발·도착만). 경유 여부는 혼잡도 데이터의 `sttn_id`로 판단한다.
- 같은 `rte_no` 표기에 서로 다른 `rte_id`가 여럿인 경우가 있다(예: `2-1하궁` ×3).
- 숫자가 없는 `rte_no`도 있다: `둘레길`, `호저`, `횡성순환-*`, `둔내순환-*`, `고장`, `공차`, `조조`.
- `ctpv_cd=42` 전체에는 다른 지역(예: 금산) 노선도 섞여 있다 → 반드시 `sgg_cd`로 거른다.
