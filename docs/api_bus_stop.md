## 4. 응답
구조는 다른 API와 같다(`Response.body.items.item[]`, 오류도 HTTP 200 + `Error`).

| 필드 | 국문 | 타입 | 예시 (원주) |
|---|---|---|---|
| `opr_ymd` | 운행일자 | 문자열 | `"20260101"` |
| `sttn_id` | 정류장ID | 문자열 | `"4379191"` |
| `sttn_nm` | 정류장명 | 문자열 | `"연세대정문"` |
| `sttn_ars_no` | ARS번호 | 문자열 | `"~"` (= 값 없음) |
| `ctpv_cd` / `ctpv_nm` | 시도 | 문자열 | `"51"` / `"강원특별자치도"` |
| `sgg_cd` / `sgg_nm` | 시군구 | 문자열 | `"51130"` / `"원주시"` |
| `emd_cd` / `emd_nm` | 읍면동 | 문자열 | `"5113025000"` / `"흥업면"` |

- `"~"`는 원천 시스템의 공백값. 원주는 `sttn_ars_no`가 전부 `"~"`로 보임 → 빈 값으로 취급.
- 중복 행 없음(847행 = 고유 `sttn_id` 847개).
- 혼잡도 하루치의 고유 `sttn_id` 792개가 **전부** 정류장 목록에 존재.

### 평일 재확인 (2026-04-15 수요일)
- 혼잡도 25,701행, 고유 `rte_id` 143개(공휴일 113개보다 많음).
- 캠퍼스 정류장을 지나는 `rte_id` 14개 — 여전히 **30, 31, 34, 34-1 계열**만:
  `30연세대`, `30연세대(복편상지대)`, `30연세대(왕편상지대)`, `30연세대발원주역미경유`, `30연세대종료(원주역미경유)`, `31귀래`, `31귀래(복편원주역)`, `31귀래3리-귀래`, `31단강`, `31용암`, `31운남`, `34-1`, `34연세대`, `34연세대(복편원주역)`
- `111(연세대경유)`(43705802)는 평일에도 이 10개 정류장 기록이 없음(4/15 하루 14행, 13개 정류장 — 일반 111번 경로와 거의 같음). 하지만 **팀원 확인 결과 실제로는 연세대에 들어간다** → 합성데이터에서 해당 구간이 누락된 것으로 보고, CLAUDE.md의 "수동 포함 목록"으로 보완한다.

### 정류장 목록의 특성
- 정류장 목록은 **그날 운행한 정류장만** 나온다: 2026-01-01 847개 → 2026-04-15 1,164개 (1월에만 44개, 4월에만 361개).
- 매지휴게소(`4381471`, `4381481`)는 4월 15일 목록에 없음(그날 운행 없음). 같은 ID가 다른 정류장으로 바뀐 사례는 없었다.
- 버스노선 API는 2026-04-15에도 `ctpv_cd=42`로만 조회됨.
