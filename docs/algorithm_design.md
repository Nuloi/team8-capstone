# 혼잡 판단·예측 알고리즘 설계

작성: 2026-10-06 (팀 합의 — 변경 시 사용자 확인). 구현 전 설계 문서.
목표: "언제(시간대·기간), 어느 노선·구간이 혼잡해지는가"를 판단하고 예측해 웹에 보여준다.
입력: `data/clean/51130/*.csv` (미래캠퍼스 노선만, 2025년), 공휴일·학사일정 설정.

## 0. 데이터 제약 → 설계 원칙
| 제약 | 원칙 |
|---|---|
| 시간 해상도 1시간(`tzon`) | 결과는 "몇 시대"까지만 말한다 |
| 합성데이터, 한 운행 안에서도 값 변동 큼 | 개별 관측이 아니라 **날별 평균의 분포**로 판단 |
| 2025년 1년치뿐 | 연도 계절성은 학습 불가. 대신 **학기/방학/시험기간** 차이를 쓴다 |
| 칸마다 관측일 수가 다름 (새벽·외곽은 적음) | 관측이 적은 칸은 상위 평균 쪽으로 **보정(shrinkage)** |
| `cgst`는 45명 기준 재차율 **추정** | 화면·발표에 "추정" 표기 |

## 1. 분석 단위 ("칸")
```
노선(base_no 합산 / rte_id 변형) × 정류장(sttn_id) × 기간(학기·시험·방학·계절학기)
  × 일자 유형(평일·토요일·일요일·공휴일) × 시간대(tzon)
```
- 칸 안에서 **날짜마다 평균 cgst를 하나** 만든다 → "날별 값" 목록 `x_1 … x_d` (d = 관측일 수)
- 이후 모든 지표는 날별 값 기준이다.

## 2. 1단계 — 혼잡 패턴 지수 (규칙 기반, 설명 가능)
| 지표 | 정의 | 의미 |
|---|---|---|
| 수준 `L` | 보정 평균 `(d·mean(x) + k·prior) / (d + k)` — `prior` = 같은 노선·기간·일자유형·시간대의 전 정류장 평균, `k` = 보정 강도(설정값, 초안 5) | 보통 얼마나 붐비나 |
| 상위값 `P90` | 날별 값의 90분위 | 붐비는 날엔 얼마나 |
| 빈도 `F` | `x_i ≥ T_혼잡`인 날의 비율 | 얼마나 자주 |
| 시간 지속 `D_t` | 같은 날·정류장에서 `T_혼잡` 이상이 연속된 시간 수의 평균 | 얼마나 오래 |
| 구간 지속 `D_s` | 같은 날·시간대에 노선 순서상 연속으로 `T_혼잡` 이상인 정류장 수의 평균 (rte_id 단위) | 어디까지 이어지나 |

### 결과물
- **혼잡 등급 3단계 (임시 기준, 팀 결정 2026-10-06)** — `T1` 여유 / `T2` 보통 / `T3` 혼잡
  - 경계: 수준 `L` 분포의 **하위 1/3(33분위)·상위 1/3(67분위)** 지점에서 자른다 → 칸들이 대략 같은 비율로 세 등급에 나뉜다.
  - 경계값은 실행할 때마다 **그때까지의 데이터로 다시 계산**하고 결과 파일에 함께 기록한다(웹이 범례로 쓸 수 있게).
  - 분포 기준: 기본번호(base) 단위 칸들의 `L`. 변형(route) 단위에도 같은 경계를 적용한다.
  - **임시 기준**이다 — 2025년 수집이 끝나면 분위수 유지 / 고정값(예: 좌석 기준 약 24명 ≈ 53%) / 4단계 전환 중에서 다시 결정한다. 그래서 등급 방식은 코드에 박지 않고 설정값으로 둔다.
  - `T_혼잡`(빈도 `F`·지속 `D` 계산 기준) = `T3` 경계(67분위).
- **상습 혼잡 표시** — `F`와 `D_t`가 모두 기준 이상인 칸 (기준 미정)
- **혼잡 시간대 구간** — 정류장·노선·기간·일자유형별로 등급이 `T3` 혼잡인 **연속 시간대**와 `L`이 가장 높은 **피크 시간**
  - 예: "학기 평일 34번 원주의료원: 10~13시 혼잡, 피크 12시"
- **덜 혼잡한 시간 추천** — `T3` 혼잡 칸에 대해 같은 정류장·노선의 **±2시간** 중 `L`이 가장 낮은 시간대 (등급이 한 단계 이상 낮을 때만 추천)

## 3. 2단계 — 혼잡도 예측 모델
- **예측 대상(y)**: (날짜, 시간대, 노선 rte_id, 정류장)의 **날별 평균 cgst** → 추정 인원 `round(y×45/100)`, 등급(1단계와 같은 경계)으로도 변환
- **입력 요소(X)**
  | 분류 | 요소 | 출처 |
  |---|---|---|
  | 시간 | `tzon`, 요일(`dow_cd`), 일자 유형, 월 | clean 데이터 |
  | 기간 | 학기/시험/방학/계절학기 | `config/academic_calendar.csv` |
  | 특일 | 공휴일 여부, **연휴 전날·다음날** | 공휴일 목록 |
  | 노선 | `base_no`, `rte_id` (범주형) | clean 데이터 |
  | 정류장 위치 | 캠퍼스 정류장 여부, 노선 내 상대 위치(`sttn_seq ÷ 최대 순서` → 앞·중간·끝), 방면(정류장명 괄호: 시내방면·귀래방면 등) | 캠퍼스 정류장 목록, clean 데이터 |
  | 이력 | 해당 정류장·시간대의 과거 평균 수준 | **학습 기간 데이터로만** 계산 (누수 방지) |
- **모델**: scikit-learn `HistGradientBoostingRegressor` (범주형 직접 지원, 추가 의존성 `scikit-learn`)
- **검증**: **기간 분할** — 예) 1~10월 학습, 11~12월 평가. 무작위 분할 금지(같은 날 데이터가 섞여 성능이 부풀려짐)
  - 지표: MAE(재차율 %p), 등급 일치율
  - **기준선**: 1단계 지수 `L`을 그대로 예측값으로 쓸 때의 MAE — 모델이 이보다 낫지 않으면 지수를 쓴다
- **활용**: 특정 날짜·시간에 대해 예상 재차율·인원·등급을 표시. 다른 연도 예측 시 그해 학사일정·공휴일 필요.

## 4. 웹 파트에 넘길 결과물 (산출물 초안)
**역할 경계**: 이 저장소는 알고리즘까지 구현하고 결과를 **파일로 넘긴다.** 웹 화면 구현은 다른 팀원 담당이다.
결과 파일의 컬럼·형식은 웹 팀원과의 계약이므로 확정 전에 함께 맞춘다(형식: CSV `utf-8-sig`, 필요하면 JSON 추가 — 미정).

| 웹 기능 | 넘길 결과 | 출처 |
|---|---|---|
| 혼잡 등급 3단계 (색) + 범례 | 칸별 등급, 등급 경계값 | 1단계 `L` / 2단계 예측값 |
| 혼잡 시간대 구간·피크 | 정류장·노선·기간·일자유형별 혼잡 시작·끝 시간, 피크 시간 | 1단계 |
| 예상 재차율·인원 | 칸별(또는 날짜별) 예상 `cgst`, `est_pax` | 2단계 (없으면 1단계 `L`) |
| 덜 혼잡한 시간 추천 | 혼잡 칸별 추천 시간대와 그때의 등급·수준 | 1단계 (2단계 예측으로 대체 가능) |

## 5.2 1단계 구현 (2026-10-06)
실행: `python -m bus_congestion pattern --year 2025` (먼저 `clean`) → `data/result/51130/2025/`
코드: `src/bus_congestion/pattern.py`, 설정: `config/settings.toml [pattern]`

| 파일 | 한 행 | 주요 컬럼 |
|---|---|---|
| `pattern_base.csv` | 기본번호 × 정류장 × 기간 × 일자유형 × 시간대 | `n_days`, `n_obs`, `cgst_mean_raw`, `cgst_p90`, `level`(L), `est_pax`, `grade`(T1~T3), `grade_name`, `congested_days_ratio`(F), `duration_hours`(D_t) |
| `pattern_route.csv` | 변형(rte_id) × 정류장 순서 × … | 위 + `rte_no`, `sttn_seq`, `segment_stops`(D_s) |
| `congestion_windows.csv` | 기본번호 × 정류장 × 기간 × 일자유형의 T3 연속 구간 | `start_tzon`, `end_tzon`(포함, 예 10~13 = 10:00~13:59), `hours`, `peak_tzon`, `peak_level` |
| `recommendations.csv` | T3 칸 하나 | `from_tzon/level/grade`, `rec_tzon/level/grade`, `shift_hours`(음수=더 일찍) |
| `grade_thresholds.csv` | 1행 | `t_low`, `t_high`, 데이터 기간, `provisional=True` — 웹 범례용 |

- `duration_hours`: 그 시간대가 혼잡했던 날들에 대해, 혼잡이 이어진 시간 수의 평균 (혼잡한 날이 없으면 빈칸)
- `segment_stops`: 그 정류장이 혼잡했던 날·시간에 대해, 노선 순서상(관측된 정류장 기준) 연속 혼잡 정류장 수의 평균
- 추천은 등급이 T3보다 낮은 시간만 후보, `L` 최저 → 같으면 가까운 시간

### 첫 실행 결과로 본 점 (2025-01-01~05-25, 145일)
- 임시 경계: T1 < 9.04 ≤ T2 < 13.19 ≤ T3 (재차율 %, 약 4명·6명)
- 기간 효과 확인: 평균 L 학기 12.5 / 시험 13.75 / 계절학기 10.9 / 방학 10.6. 연세대 정류장 평일은 학기 11.6 vs 방학 7.4
- **주의 1**: 1/3 분위수 경계는 상위 1/3을 무조건 "혼잡"으로 만들어, 시내 일부 정류장은 08~21시 전체가 혼잡 구간으로 나온다 → 최종 기준 결정 시 고려
- **주의 2**: 칸당 관측일 수 중앙값 3일 (25%가 1일) → 보정(`shrinkage_k`)의 영향이 크다. 1년치가 모이면 완화
- 노선 목록에 없는 rte_id가 생기면 기본번호가 비므로, 수집 기간에 맞춰 `reference` 스냅샷을 추가해야 한다
